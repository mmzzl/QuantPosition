# Feature Specification: 持仓管理系统 + Vue3 前端

**Feature Branch**: `003-holdings-frontend`  
**Created**: 2026-05-14  
**Status**: Draft  
**Input**: 用户需求：完善 holdings.py 的增删改查和历史记录，创建 Vue3 前端页面，实现用户、角色、权限管理

---

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 用户注册与登录 (Priority: P1)

新用户可以通过注册创建账号，已有用户可以登录进入系统。

**Why this priority**: 这是所有功能的基础，用户必须先登录才能使用持仓管理和后台管理功能。

**Independent Test**: 可以通过注册新用户、登录、登出操作独立测试。

**Acceptance Scenarios**:

1. **Given** 用户访问注册页，**When** 填写用户名、密码并提交，**Then** 系统创建账号并返回成功，用户可使用账号登录
2. **Given** 用户访问登录页，**When** 输入正确的用户名和密码，**Then** 系统验证通过，返回 JWT token，用户进入系统
3. **Given** 已登录用户，**When** 点击登出，**Then** 清除登录状态，返回登录页

---

### User Story 2 - 持仓买入与卖出 (Priority: P1)

用户可以买入新持仓、卖出已有持仓，系统记录所有交易。

**Why this priority**: 持仓管理是核心功能，买卖操作是用户主要操作。

**Independent Test**: 可以通过添加持仓、卖出操作独立测试，数据会记录到交易历史。

**Acceptance Scenarios**:

1. **Given** 用户访问持仓列表为空，**When** 填写股票代码、数量、成本价并提交买入，**Then** 持仓列表显示新持仓
2. **Given** 用户持有某股票1000股，**When** 卖出500股，**Then** 持仓数量更新为500股，产生卖出交易记录
3. **Given** 用户访问持仓历史，**When** 查看历史记录，**Then** 显示所有买入和卖出记录，包含时间、股票代码、类型、数量、价格、总额

---

### User Story 3 - 持仓查看与汇总 (Priority: P1)

用户可以查看持仓列表、组合汇总、盈亏情况。

**Why this priority**: 投资者需要随时了解自己的持仓状况和盈亏。

**Independent Test**: 可以通过访问持仓列表和汇总页面独立测试。

**Acceptance Scenarios**:

1. **Given** 用户持有多个持仓，**When** 访问持仓列表，**Then** 显示所有持仓的股票代码、名称、数量、成本、市值、盈亏、盈亏比例
2. **Given** 用户访问组合汇总页，**Then** 显示总持仓数、总成本、总市值、未实现盈亏、盈亏比例、已实现盈亏

---

### User Story 4 - 管理员用户管理 (Priority: P2)

管理员可以查看用户列表、编辑用户信息、修改密码、分配角色、删除用户。

**Why this priority**: 管理员需要管理系统用户，维护用户权限。

**Independent Test**: 可以通过管理员操作用户 CRUD 独立测试。

**Acceptance Scenarios**:

1. **Given** 管理员访问用户列表，**When** 查看用户列表，**Then** 显示所有用户信息：用户名、邮箱、角色、状态、创建时间
2. **Given** 管理员点击编辑用户，**When** 修改用户信息并保存，**Then** 用户信息更新成功
3. **Given** 管理员点击修改密码，**When** 输入新密码并确认，**Then** 用户密码更新成功
4. **Given** 管理员点击分配角色，**When** 选择角色并确认，**Then** 用户角色更新成功
5. **Given** 管理员点击删除用户，**When** 确认删除，**Then** 用户从系统中删除

---

### User Story 5 - 管理员角色与权限管理 (Priority: P2)

管理员可以创建角色、编辑角色信息、分配权限、删除角色。

**Why this priority**: 角色和权限管理是 RBAC 系统的核心，管理员需要维护系统权限结构。

**Independent Test**: 可以通过管理员操作角色 CRUD 独立测试。

**Acceptance Scenarios**:

1. **Given** 管理员访问角色列表，**When** 查看角色列表，**Then** 显示所有角色：角色名、描述、权限数量
2. **Given** 管理员点击添加角色，**When** 填写角色名、描述、选择权限并保存，**Then** 新角色创建成功
3. **Given** 管理员点击编辑角色，**When** 修改角色信息或权限并保存，**Then** 角色更新成功
4. **Given** 管理员点击删除角色，**When** 确认删除，**Then** 角色从系统中删除

---

### User Story 6 - 管理员查看所有用户持仓 (Priority: P2)

管理员可以查看所有用户的持仓情况。

**Why this priority**: 管理员需要监控所有用户的持仓数据。

**Independent Test**: 可以通过管理员访问所有用户持仓页面独立测试。

**Acceptance Scenarios**:

1. **Given** 管理员访问所有用户持仓页，**Then** 显示所有用户的持仓汇总，包括用户ID、持仓数量、总市值
2. **Given** 管理员查看指定用户的持仓详情，**Then** 显示该用户的所有持仓信息

---

### Edge Cases

- 用户尝试卖出超过持有数量的股票时，系统应提示数量不足
- 用户尝试添加已持有的股票时，系统应累加数量并重新计算平均成本
- 用户修改密码时，新密码与确认密码不一致应提示错误
- 管理员删除用户时，应检查该用户是否有关联数据
- 用户未登录访问需要认证的页面时，应跳转到登录页
- 用户操作无权限功能时，应提示权限不足

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持用户注册，创建新账号
- **FR-002**: 系统 MUST 支持用户登录，返回 JWT token 用于身份验证
- **FR-003**: 系统 MUST 支持用户登出，清除登录状态
- **FR-004**: 系统 MUST 支持获取当前登录用户信息
- **FR-005**: 系统 MUST 支持买入/添加持仓，包含股票代码、名称、数量、平均成本
- **FR-006**: 系统 MUST 支持卖出持仓，扣减持仓数量并记录交易
- **FR-007**: 系统 MUST 支持删除持仓
- **FR-008**: 系统 MUST 支持获取持仓列表，分页显示
- **FR-009**: 系统 MUST 支持获取持仓历史记录，包含买入和卖出记录
- **FR-010**: 系统 MUST 支持获取交易记录列表，分页显示
- **FR-011**: 系统 MUST 支持删除交易记录
- **FR-012**: 系统 MUST 支持获取已实现盈亏
- **FR-013**: 系统 MUST 支持获取组合汇总，包含总成本、总市值、未实现盈亏、盈亏比例、已实现盈亏
- **FR-014**: 系统 MUST 支持获取卖出规则和设置卖出规则
- **FR-015**: 系统 MUST 区分管理员和普通用户权限，管理员可访问所有用户数据
- **FR-016**: 系统 MUST 支持用户列表查询（管理员）
- **FR-017**: 系统 MUST 支持获取用户详情
- **FR-018**: 系统 MUST 支持更新用户信息
- **FR-019**: 系统 MUST 支持修改用户密码
- **FR-020**: 系统 MUST 支持为用户分配角色
- **FR-021**: 系统 MUST 支持删除用户（管理员）
- **FR-022**: 系统 MUST 支持角色列表查询
- **FR-023**: 系统 MUST 支持创建角色
- **FR-024**: 系统 MUST 支持更新角色
- **FR-025**: 系统 MUST 支持删除角色
- **FR-026**: 系统 MUST 支持为角色分配权限
- **FR-027**: 系统 MUST 支持权限列表查询
- **FR-028**: 前端 MUST 提供登录页面，包含用户名、密码输入和登录按钮
- **FR-029**: 前端 MUST 提供注册页面，包含用户名、密码、确认密码输入
- **FR-030**: 前端 MUST 提供首页/仪表盘，显示用户信息和持仓概览
- **FR-031**: 前端 MUST 提供用户管理页面，包含用户列表、搜索、添加、编辑、修改密码、分配角色、删除功能
- **FR-032**: 前端 MUST 提供角色管理页面，包含角色列表、添加、编辑、删除、权限分配功能
- **FR-033**: 前端 MUST 提供持仓列表页面，显示持仓信息
- **FR-034**: 前端 MUST 提供买入页面，填写持仓信息并提交
- **FR-035**: 前端 MUST 提供卖出页面，选择持仓并填写卖出数量和价格
- **FR-036**: 前端 MUST 提供持仓历史页面，显示历史交易记录
- **FR-037**: 前端 MUST 提供组合汇总页面，显示整体持仓统计
- **FR-038**: 前端 MUST 保护路由，未登录用户访问需要认证的页面时跳转到登录页

### Key Entities *(include if feature involves data)*

- **用户 (User)**: 系统用户，包含用户名、密码、邮箱、角色、状态、创建时间
- **角色 (Role)**: 用户角色，包含角色名、描述、权限列表
- **权限 (Permission)**: 系统权限，包含权限名、描述
- **持仓 (Holding)**: 用户持仓，包含用户ID、股票代码、股票名称、数量、平均成本、最高价、卖出规则、创建时间、更新时间
- **交易记录 (Transaction)**: 持仓交易记录，包含用户ID、股票代码、类型（买入/卖出）、数量、价格、总额、创建时间

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在 2 分钟内完成注册流程
- **SC-002**: 用户登录成功后 3 秒内跳转到首页
- **SC-003**: 持仓买入操作成功后会立即显示在持仓列表中
- **SC-004**: 卖出操作成功后会更新持仓数量并生成交易记录
- **SC-005**: 用户可以查看完整的持仓历史记录，包含所有买卖操作
- **SC-006**: 组合汇总页面准确显示总成本、总市值、盈亏数据
- **SC-007**: 管理员可以完成用户和角色的完整 CRUD 操作
- **SC-008**: 页面加载时间不超过 2 秒
- **SC-009**: 95% 的用户可以顺利完成首次登录和持仓操作

---

## Assumptions

- 用户已有稳定的网络环境访问系统
- MongoDB 数据库服务正常运行
- 系统只需要支持桌面端浏览器（1024px 以上）
- 管理员账号初始由系统创建或通过数据库直接设置
- 用户对自己的持仓数据拥有完整操作权限
- 角色和权限的变更实时生效
